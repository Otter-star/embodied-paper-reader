# 精读结构与配图

完整精读按以下顺序组织，对话答复也保留这条讲解顺序。用户指定其他格式时遵从其要求。主题选文采用路线表，摘要概览只覆盖实际取得的材料。

| 部分 | 交付内容 |
| --- | --- |
| 动机 | 从 Introduction 提取已有做法、具体缺口、作者选择该方向的理由。作者原述与读者解释分别归因。 |
| 架构 | 解释模块职责和连接关系，配合关键架构图逐项定位。标明作者的改动及继承的组件。 |
| 训练方式 | 按实际阶段记录初始权重、数据、监督信号或奖励、损失、可训练参数范围及产物。说明阶段之间的承接。 |
| 数据集 | 写清来源、选择和预处理，展示一条样本的字段、时间结构、动作语义及已知尺寸。磁盘原始格式与加载器输出分别注明。 |
| 信息流 | 分别追踪训练与推理经过的模块。训练说明监督目标、损失和参数更新；推理说明解码、后处理和执行循环。 |
| 完整例子 | 用一个任务贯穿数据、模块及输入输出。真实样本给来源，教学示例明确标注。数值和张量尺寸仅使用原文、官方实现或已说明的推导。 |

随后说明实验支持、局限、四类复现条件及关联阅读。每段优先加粗 1–2 处重点，数字附近保留基线、平台、单位和原文定位。

复用旧导读后，检查新增表格、图注与原有段落是否重复解释同一内容。将必要限定并入对应位置，保留一份完整讲解，避免重复堆叠训练细节、图注或复现条件。

训练范式按论文实际说明。例如，监督行为克隆、强化学习及推理时规划各有不同的目标与信息流；预训练模型来源与作者实施的训练阶段分别交代。缺失的参数或阶段写出已查位置及缺口，受影响的判断记待验证。

## 裁图并交付

选择能解释关键方法或支撑主结论的图表。先查看 PDF 页面，确定包含必要图例、坐标、子图标签与完整图注的区域。可从仓库根目录运行下列脚本，页码从 1 开始，clip 单位为 PDF 点、原点在页面左上角。

```powershell
python -X utf8 scripts/extract_figure.py <论文.pdf> <local下图片.png> --page 4 --clip 100 68 512 240 --figure "Figure 2" --source <一手来源URL> --version <规范版本>
```

坐标根据每张页面重新确定。脚本保存 PNG 和同名 JSON，后者记录版本、来源、PDF 哈希、页码及裁剪坐标。生成后必须调用多模态看图工具（如 view_image）实际打开最终 PNG，检查文字可读、内容完整、编号及版本相符。环境或模型不具备看图能力时，将可读性断言记为待验证，不能凭脚本退出码成功判通过。提取失败时记录缺口；配图交付状态单独核验。

图片放在对应讲解附近，对话使用本地图片的绝对路径内嵌展示。HTML 或 Markdown 交付稿可以使用同目录相对图片路径。图片只作原图裁剪，中文讲解放在图外，保留原始标签便于对照。

Zotero 文本笔记中的图号、解释与一手链接须可回查。当前同步脚本只上传论文 PDF 和 HTML 笔记，未实现图片资源导入。若交付稿包含本地相对图片，另备引用原文图号与链接的文本笔记稿用于同步，并如实报告图片交付在对话和本地导读。用户明确要求 Zotero 内嵌图片时，将受影响的图片导入子项列为待验证。
