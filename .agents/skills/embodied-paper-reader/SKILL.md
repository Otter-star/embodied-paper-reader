# 具身智能论文阅读

本 Skill 随 embodied-paper-workflow 仓库使用，也可通过用户级目录链接在其他项目调用。先将本 SKILL.md 的实际路径解析出来（Python `Path(<本文件路径>).resolve()` 会跟随目录链接），该文件的 `parents[3]` 是仓库根目录。读取该根目录下 `docs/acceptance.md` 的状态、适用范围和本次所需检查项。由 Agent 完成检索、选版、全文阅读与导读，仓库脚本负责查库、同步和本机回读。

跨项目调用时，命令的工作目录设为解析出的仓库根目录。以下 `scripts/` 与 `local/` 均相对该根目录，沿用同一份本机审计和笔记更新基准。调用所在项目的其他任务继续遵从该项目指令。用户级安装只改变 Skill 的发现位置；访问仓库或本机 API 受限时，按当前工具权限机制处理。

用户请求安装、更新或修复环境时，读取仓库根目录的 [INSTALL.md](../../../INSTALL.md)。本 Skill 依赖完整仓库，不能只复制当前目录；若解析出的根目录缺少 `scripts/zotero_sync.py` 或 `docs/acceptance.md`，先修复安装，不猜测其他路径。安装不触发 Zotero 写入授权。使用时按自然语言判断下方范围，无需用户提供固定提示词。

## 确定交付范围

用户要求“按工作流执行”“保存任务”或“继续某个任务”时，先读[持久任务入口](references/workflow-run.md)。在当前 Codex 对话执行桌面任务，沿用下方选文、精读与入库规则；任务登记成功后继续实际工作，最后保存核验结果。普通临时问答不强制创建任务。

- 具体论文请求默认交付中文精读、同版 PDF 和 Zotero 导读子笔记。用户只要求解释、摘要或选文时，按该范围执行。
- 将团队、日期、标题线索与一手书目核对。只在候选无法区分且会影响选文时提问。OpenVLA 与 OpenVLA-OFT 是独立论文。
- 按主题找论文时采用核验表第 1、7 项，执行下方路线流程。用户选篇后进入单篇精读与入库。
- “我库里有 X 吗”“帮我找回 X”等请求走本仓库的只读查库入口，返回书目、已核实版本、PDF 文件可用性、笔记存在状态、核验时间和本地详单相对路径；内部 Key 及路径遵循第 6 项脱敏约定。按需列候选供定位，用户提出精读或入库后再进入对应流程。

## 主题阅读路线

记录本次时间窗、排序日期口径、实际查询及纳入／排除条件。搜索引擎的站点限定使用 `site:arxiv.org` 等有效语法；检索日志保留真正执行的查询。按核验表检查奠基、转折、期末代表与并行分支的覆盖，并说明邻近工作的取舍。

逐篇核对标题、作者、标识和日期，用一张紧凑表呈现技术变化与阅读问题。在 `local/routes/<主题与时间窗>/` 留下本轮核验记录，每项关键技术关系给实际读取的版本、一手链接、章节或图表位置及一段简短原文依据。直接引用只取支持判断所需的短句。样例路线用于检查覆盖，实际来源和读取结果由本轮取得。

向用户交付路线及本地记录位置，并报告本次向 Zotero 新增的记录数。选篇前流程只检索与读材料，通过本轮操作记录核验零写入。

路线核验记录包含以下固定字段，逐项按本次实际执行填写，证据定位到调用入口或操作历史。覆盖脚本、插件及直接 API 的写操作；授权请求与库记录写入分别说明。

| 字段 | 零写入路线的填写样例 |
| --- | --- |
| 核验时间与本次范围 | 本轮时间窗与用户选文请求 |
| zotero_sync 调用次数 | 0 |
| Zotero 库记录写操作次数 | 0 |
| 本次新增记录数 | 0，由操作历史核验 |
| 操作证据 | 实际使用的检索、阅读或只读查库入口及其记录位置 |

仅在操作历史完整且支持时填写零值；存在写操作时记录实际动作与增量，缺少操作证据时将零写入断言记待验证。

用户选中某篇后，结合上下文解析论文与版本。明确选定 v1 或限定阅读截止日时沿用该约束；仅用于路线排序的首发日期，与单篇阅读版本分别记录。选篇只指定论文且未约束版本时，采用下方默认选版规则，并在导读说明依据。

## 查库、选版和读取全文

在仓库根目录运行，所有路径随实际仓库位置解析。

```powershell
python -X utf8 scripts/zotero_lookup.py "OpenVLA"
```

该入口只读个人库。输出书目信息、附件来源和已核实的版本，完整匹配记录留在被 Git 忽略的 `local/zotero-audit/`。可用标题或标准标识符查询；空结果时换另一种线索再查。姓名、标题和出版形态仍需与一手记录交叉核对。连接失败时也遵守第 6 项脱敏约定。若调用 Zotero 插件的 `scripts/zotero.py status --json`，先从该插件 SKILL.md 定位脚本，再在同一本机进程或管道中解析，只取 `local_api_enabled_pref`、`api_running`、`connector_running` 字段；配置路径、原始输出及错误详情留在本机。

本机连接先区分执行权限和服务状态。错误含 WinError 10013 时，先通过工具的权限申请机制获准访问本机 API，再重跑同一查库入口。该环境下的 api_running=false 仅说明探测未成功，服务运行状态仍待核实。获准环境仍无法连接时，再检查 Zotero 进程、API 设置或安装位置。

先满足用户指定版本或截止日。未指定时按核验表的选版优先级复用已核实全文。需要复用某版时用其规范标识导出本地副本。

```powershell
python -X utf8 scripts/zotero_lookup.py "OpenVLA" --export-version "arxiv:2406.09246v3"
```

若库中没有合格全文，从该篇出版记录的直接 PDF 链接取正式版，其次取最新可核实 arXiv 修订。库内未能认定版本的附件先核验来源。文件下载或解析失败时报告具体缺口。

**同版优先选正文能选字、高亮的附件。** 查库时查看每份 PDF 的 `body_text`。新取得的候选先用 `python scripts/zotero_sync.py --check-text <PDF>` 抽查。若只找到扫描件、部分可选或结果不确定，再检查该版本的出版记录或作者提供的同版全文入口。在已核实的同版候选中优先选抽查页均可选字的 PDF，其次选部分可选的副本。记录实际检查的来源和结果。其他修订版按选版规则单独处理。

读取选定版本的完整 PDF 或同版 HTML，核验图表、实验协议和局限。正文与入库 PDF 必须版本一致。用正式版时，章节号和作者以正式版为准。复现入口读取官方仓库并记录实际版本或访问日期。仅有摘要时按摘要级规则交付，精读和入库的缺项保留待验证。

PDF 首页无文字时，用 OCR 辅助并实际查看原页，按同步输入约定准备绑定原文件哈希的身份证据。导读头部和交付回复都写明所选附件的正文文字层结果。全文件未检出文字层时写“本附件无法按文字高亮”，部分可选或不确定时写明抽查页和限制。外部 OCR 摘录只用于身份核验。同步后以实际附件的回读结果为准；库中已有较差副本或多个副本需消歧时，保留原件及批注，报告待处理的原因。

同版 PDF 与 HTML 的自动图表编号可能不同。入库导读以附件 PDF 编号定位，借助 HTML 检索后回到 PDF 核对，并在核验记录中列出实际用到的编号对应关系。

正式版缺少被引用的附录时，可读取另一个明确版本作补充，分别保存来源，并在相应断言旁标出补充版本及位置。主读版本的 PDF 继续与主文导读绑定；补充来源与主读版本发生差异时并列记录，受影响的解释保留待验证。

## 写中文导读

完整精读按“动机 → 架构 → 训练方式 → 数据集 → 信息流 → 完整例子”组织，对话和本地导读采用同一顺序。先读[精读结构与配图约定](references/reading-guide.md)，再补实验支持、局限、四类复现条件及关联阅读。重要图表从所读版本 PDF 裁剪，放在相应讲解旁并实际查看裁剪结果。关键短语用 Markdown 加粗或 HTML `<strong>`。

- 强调研究问题、核心方法、结果、局限及复现门槛。数字就近带上比较对象、任务范围、单位和原文定位。试验次数写清每任务次数、任务数、随机种子数及合计所对应的方法或条件；仅使用原文支持的分解。例如“每种精度在 8 项任务上各测 10 次，合计 80 次”能明确各层计数。
- 对每项主要结论核对同版章节、表格行列或关键短句。基线称为 scratch 或“无预训练”时，说明去掉哪一阶段、哪些初始化仍保留。读分组图时，沿图例、横轴标签和分组括号确认每个数属于哪组；独立的 `Average` 若未注明涵盖范围或权重，就按图中标签引用并写明缺口。
- 在核验表分别记录作者原述与读者复算。作者只写“%”且未说明计算方式时照录；同口径成功率相减的结果用“个百分点”，注明为复算。数值相等本身无法证明二者采用同一汇总方式。对应关系待验证时，把这项限定一并带入引用该数字的笔记头部或对话结论。
- 复现分推理、微调、仿真和真机。对每项先写明要运行的动作，再沿官方文档对应小节或命令列出所需权重、数据、环境和硬件。例如仿真中，用已发布权重跑评测和重新训练权重是两个操作，示范数据是否必需分别查证。标明作者示例配置与已证实的最低要求。个人设备判断按核验表在读者询问时核验。
- 默认推荐 3 篇。对话和笔记中每篇都写明与主论文的具体技术关系、能解答的阅读问题，并附标识或一手链接和证据位置。例如，推荐基线论文时指出主论文在哪个实验用它作比较。

## 准备清单并同步

先读[同步输入约定](references/sync-input.md)，在 `local/papers/<安全标识>/` 中保存 PDF、导读 HTML、书目 JSON 和本轮内容核验表。论文材料与交接记录都保存在 Git 忽略的 `local/` 中。准备好的旧样品只有经本轮核对后才能复用。

笔记首行固定标记与版本，例如 `[embodied-paper-reader] 中文导读 · OpenVLA (2406.09246v3)`。头部写版本、取证日、已通过内容和待补原因。内容核验状态与随后获得的入库状态分别如实记录。

先完成内容核验及结论限定，再进行首次同步；入库后新发现的更正按原位更新处理。

```powershell
python -X utf8 scripts/zotero_sync.py local/papers/<安全标识>/paper.json
```

用户在本工作流中请求精读并入库已授权该次同步。首次获取或撤销后恢复 Zotero 本地授权需要用户操作窗口；选择“始终允许 / Always Allow”后，Windows 系统凭据存储会供后续进程复用。单次允许不持久化。密钥由脚本本机处理，不读取、打印或复制到审计。缺 Python 依赖时按根目录 `requirements.txt` 安装；接口不可用时先诊断当前实例。脚本适配 Zotero Desktop 10 个人库的本地 API。查库和完整重跑只读，实际补缺或更新会请求写入。

首次同步后重复同一入口，按核验表第 6 项核对回读与零增量。原位更新由笔记哈希和对象版本检查保护，检测到个人修改时保留并报告待补。导入响应或退出码不足以证明内容主张正确，仍需本轮内容核验表。

若 Zotero 编辑器规范化 HTML 导致回读差异，先在本机比较正文、链接和强调范围。确认只是等效标签、空行或链接 rel 属性变化后，将回读 HTML 保存为交付稿并重跑；实质差异须处理后再验收。

## 交付与结束

由 `scripts/paper_workflow.py` 发起时，按任务提示保存实际阶段并返回指定结构的核验结果。任务范围与本次用户请求共同决定适用项；包装器退出成功或模型输出格式正确均不能代替正文、配图和入库证据。命令与状态说明见仓库根目录 `docs/workflow.md`。

从本轮已核验的导读整理对话答复，按精读结构讲解并内嵌关键裁图。发送前逐项对照训练阶段、数据样例、训练与推理信息流，以及结果数字与单位、试验计数、复现依赖和关联论文关系。压缩篇幅时保留影响结论的条件和待验证原因。列明实际版本、核验结果、配图交付位置和本地审计相对路径。入库证据仅输出脱敏状态、时间与三类对象增量；Key、路径、原始响应和附件摘录留在本机详单。

按核验表的通过、失败、待验证、不适用汇总。红线是虚构证据、混用版本或不可比结果、虚报完成。网络、授权或证据缺口无法继续恢复时，保留已有成果，指出恢复条件。
